# Pull Request Checks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add reliable Java/Maven and CodeQL checks to pull requests and protect `main` with required checks and review approval.

**Architecture:** GitHub Actions will run two independent workflows. The backend workflow verifies the existing Spring Boot project with Java 21 and H2; the CodeQL workflow builds the nested Maven project in manual build mode so CodeQL can trace Java compilation. GitHub's `main` branch protection will require both check runs and one approving review.

**Tech Stack:** GitHub Actions, Java 21, Maven, Spring Boot, CodeQL, GitHub REST API.

---

### Task 1: Add the backend pull-request check

**Files:**
- Create: `.github/workflows/backend-check.yml`

- [ ] **Step 1: Create the workflow**

Add a workflow named `Backend Check` that runs on pull requests targeting `main`, pushes to `main`, and manual dispatch. Use `actions/checkout@v5`, `actions/setup-java@v6` with Temurin Java 21 and Maven caching, then run `mvn -B -ntp verify` from `backend`.

- [ ] **Step 2: Validate the workflow content**

Check that the workflow has read-only repository permissions, Java 21, the `backend` working directory, and the expected job name `Build and test`.

- [ ] **Step 3: Run the same verification locally**

Run `mvn -B -ntp verify` from `backend` and expect a successful build with the existing H2 context test.

- [ ] **Step 4: Commit**

```text
git add .github/workflows/backend-check.yml
git commit -m "ci: add backend pull request check"
```

### Task 2: Add CodeQL security analysis

**Files:**
- Create: `.github/workflows/codeql.yml`

- [ ] **Step 1: Create the workflow**

Add a `CodeQL` workflow for Java on pull requests targeting `main`, pushes to `main`, a weekly schedule, and manual dispatch. Grant only the permissions required to read the source and upload security findings.

- [ ] **Step 2: Configure the build**

Initialize CodeQL with Java in manual build mode, set up Temurin Java 21 with Maven caching, run `mvn -B -ntp -DskipTests package` from `backend`, then analyze the captured build.

- [ ] **Step 3: Validate the workflow content**

Check that the workflow uses CodeQL action v4 and exposes the expected job name `Analyze (java)` for branch protection.

- [ ] **Step 4: Commit**

```text
git add .github/workflows/codeql.yml
git commit -m "ci: add CodeQL security analysis"
```
