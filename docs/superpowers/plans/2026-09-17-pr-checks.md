# Pull Request Workflow Scope Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run backend build/test and Java CodeQL only for backend-related changes, while keeping manual and scheduled security scans available.

**Architecture:** Keep two independent GitHub Actions workflows. For `pull_request` and `push` events, each workflow uses a path filter whose entries are ORed; manual runs are unfiltered, and CodeQL keeps its weekly schedule. Preserve the existing job names and do not change branch protection or make either status check required.

**Tech Stack:** GitHub Actions, Java 21, Maven, CodeQL, YAML, PowerShell, Prettier.

---

### Task 1: Scope the backend build/test workflow

**Files:**
- Modify: `.github/workflows/backend-check.yml`

- [ ] **Step 1: Add the pull-request path filter**

Under `on.pull_request`, preserve `branches: [main]` and add:

```yaml

  - 'backend/**'
  - '.github/workflows/backend-check.yml'
```

- [ ] **Step 2: Add the push path filter**

Under `on.push`, preserve `branches: [main]` and add the same `paths` list. Leave `workflow_dispatch` without a path filter.

- [ ] **Step 3: Preserve the existing backend job contract**

Keep `name: Backend Check`, job ID `build-and-test`, job name `Build and test`, `contents: read`, Java 21, Maven caching, `working-directory: backend`, and `mvn -B -ntp verify` unchanged.

- [ ] **Step 4: Inspect the resulting trigger block**

Confirm that the backend workflow has filtered `pull_request` and `push` events, an unfiltered `workflow_dispatch`, and no CodeQL-specific event or path.

- [ ] **Step 5: Confirm repository protection is unchanged**

Run the following in one PowerShell session before and after the workflow edits:

```powershell
$before = gh api repos/duygri/do-an-htttdn-crm/branches/main/protection | ConvertFrom-Json
$beforeSnapshot = [ordered]@{
  required_status_checks = $before.required_status_checks
  required_pull_request_reviews = $before.required_pull_request_reviews
  required_conversation_resolution = $before.required_conversation_resolution
  enforce_admins = $before.enforce_admins
} | ConvertTo-Json -Depth 10

# Apply workflow edits, then run the read-back:
$after = gh api repos/duygri/do-an-htttdn-crm/branches/main/protection | ConvertFrom-Json
$afterSnapshot = [ordered]@{
  required_status_checks = $after.required_status_checks
  required_pull_request_reviews = $after.required_pull_request_reviews
  required_conversation_resolution = $after.required_conversation_resolution
  enforce_admins = $after.enforce_admins
} | ConvertTo-Json -Depth 10
if ($beforeSnapshot -cne $afterSnapshot) { throw 'Branch protection changed unexpectedly.' }
$afterSnapshot
```

Expected: the before/after snapshots are identical; in the current repository, `required_status_checks` is `null`. The `gh api` command requires an authenticated account with permission to read branch protection.
