# Pull Request Workflow Scope Implementation Plan

> **Goal:** Run backend build/test and Java CodeQL only for backend-related changes, while keeping manual and scheduled security scans available.

## Architecture

GitHub Actions will keep two independent workflows. For `pull_request` and `push` events, each workflow uses path filters for the backend area and its own configuration file. `workflow_dispatch` remains unfiltered, and CodeQL keeps its weekly schedule. The current branch-protection approval and conversation-resolution settings are not changed.

### Task 1: Scope the backend check

**File:** `.github/workflows/backend-check.yml`

- Add `paths` under `pull_request` for `backend/**` and `.github/workflows/backend-check.yml`.
- Add the same `paths` under `push` for `main`.
- Leave `workflow_dispatch` without paths so it can be run manually at any time.
- Preserve the workflow name `Backend Check`, job name `Build and test`, Java 21, Maven caching, `backend` working directory, and `mvn -B -ntp verify`.

### Task 2: Scope the CodeQL scan

**File:** `.github/workflows/codeql.yml`

- Add `paths` under `pull_request` for `backend/**` and `.github/workflows/codeql.yml`.
- Add the same `paths` under `push` for `main`.
- Leave `schedule` and `workflow_dispatch` unfiltered.
- Preserve the `30 2 * * 1` UTC schedule, Java language, manual build mode, Java 21, Maven package step, job name `Analyze (java)`, and CodeQL permissions.

### Task 3: Validate trigger behavior

- Confirm both workflow files parse as YAML and retain the expected event-specific filters.
- Confirm the path matrix: backend-only runs both; frontend-only/docs-only runs neither; each workflow file runs its corresponding workflow; mixed backend plus frontend/docs runs both.
- Confirm no branch-protection setting is changed by this work.
- Run `git diff --check`.

### Task 4: Verify the remote PR

- Commit the workflow changes with a focused `ci:` message.
- Push to `codex/fix-customer-sequence-language`.
- Confirm PR #47 contains the updated workflows and report any GitHub Actions result that requires follow-up.
