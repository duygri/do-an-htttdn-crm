# Pull Request Workflow Scope Implementation Plan

> **Goal:** Run backend build/test and Java CodeQL only for backend-related changes, while keeping manual and scheduled security scans available.

## Architecture

GitHub Actions will keep two independent workflows. For `pull_request` and `push` events, each workflow uses a path filter. Paths within one trigger are ORed. Manual runs are not path-filtered, and CodeQL keeps its weekly schedule. The current `main` branch settings are preserved: the two status checks must not become required, while the approving-review and conversation-resolution rules remain unchanged.

### Task 1: Scope the backend check

**File:** `.github/workflows/backend-check.yml`

- Add `paths` under `pull_request` for `backend/**` and `.github/workflows/backend-check.yml`.
- Add the same `paths` under `push` for `main`.
- Leave `workflow_dispatch` without paths so it can be run manually at any time.
- Preserve the workflow name `Backend Check`, job name `Build and test`, Java 21, Maven caching, `backend` working directory, `mvn -B -ntp verify`, and workflow-level `contents: read`.

### Task 2: Scope the CodeQL scan

**File:** `.github/workflows/codeql.yml`

- Add `paths` under `pull_request` for `backend/**` and `.github/workflows/codeql.yml`.
- Add the same `paths` under `push` for `main`.
- Leave `schedule` and `workflow_dispatch` unfiltered.
- Preserve the `30 2 * * 1` UTC schedule, Java language, manual build mode, Java 21, Maven package step, and job name `Analyze (java)`.
- Preserve job-level permissions: `actions: read`, `contents: read`, and `security-events: write`.

### Task 3: Validate trigger behavior

- Run `npx --yes prettier@3 --parser yaml .github/workflows/backend-check.yml .github/workflows/codeql.yml > $null` and expect exit code 0 for valid YAML.
- Run `git diff --check` and expect no output or errors.
- Confirm the event matrix: filtered PR/push to `main`; unfiltered manual dispatch for both; unfiltered Monday `30 2 * * 1` UTC schedule for CodeQL.
- Confirm the path matrix: backend-only runs both; frontend-only/docs-only/unrelated-only runs neither; each workflow file runs its corresponding workflow; mixed backend plus frontend/docs runs both.
- Confirm no branch-protection setting is changed and the two status checks remain non-required.
